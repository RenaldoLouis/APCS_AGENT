## Existing membership and roster checks

The 9 October 2026 change separates performance scheduling from orchestra attendance on Admin Page. Use updated frontend and backend source together. These steps are for the owner's browser verification; no production publication or admission change is implied.

1. Open a draft planning event. Confirm **Performance Sessions** and its unassigned pool appear above **Orchestra Attendance**, which has a separate table and **Add orchestra group** button. Existing attendance groups should appear only below; existing competition groups stay above.
2. Assign an eligible child to a performance group. Confirm the child leaves the upper unassigned pool. Add an orchestra attendance group with venue/date; it should not request a performer session. Its optional planned orchestra session is selected from existing Orchestra Settings, rather than creating a new time.
3. Search for that same child in the attendance row's selector. Their name, performance group and teacher should help identify the registration. Select them and confirm their upper performance card stays in place. For ensembles, one selected registration covers its stored roster; the table count is registrations, not an admission headcount.
4. Select a second eligible child for attendance before assigning their performance. They should remain in the upper unassigned pool. Assign their performance and confirm their attendance stays selected below.
5. Save Changes, reopen/refresh the page and verify both assignments for each child. Save uses the existing revision guard; if another staff member saves first, refresh and reconcile the conflict rather than overwriting their draft.
6. Remove a child from attendance; verify their performance stays. Discard and confirm attendance returns. Remove a performance card; verify attendance stays and the child returns to the eligible performance pool. Discard again to restore the saved state.
7. Add another attendance group. Search the second group selector by that child's performer or teacher name. A child already assigned to the first group should appear disabled with **Already assigned: [first group]**, so staff can see why they cannot select them again. Duplicate performance membership and duplicate attendance membership must be rejected by the backend. One membership of each type remains valid. Edit/delete attendance groups and confirm the upper board is unaffected. Clear All explicitly affects both sections; use Discard to restore a saved draft during this check.
8. In each group selector, search for a solo performer, the second ensemble member and a teacher; try mixed case and surrounding spaces. Confirm the options show teacher/performance context, preserve current selections and identify attendees assigned elsewhere. Confirm **Assigned Registrants** has a plain heading without a filtered/total count badge. Check the roster below: each registration should show performer names, teacher, performance group and orchestra group/venue/date. Search that roster by performer or teacher; only matching registration rows should remain, while all group editors remain available. Clear to restore the roster, and verify the no-match/empty messages and pagination beyond 10 registrations. Repeat in a published read-only plan; group selections remain read-only and the roster stays searchable. Switching events resets the roster search. Check narrow layouts: tables scroll horizontally, headings/search/buttons wrap, and white-card styling matches the performance panels above. Overview compares performances only; Export retains separate worksheets for all groups.
9. On an approved isolated test event, save valid performance times and run the normal preview → publish → numbered-seat generation → readiness flow. A dual member must stay listed for public and winner performance selection at their competition session, subject to normal award/day/seat rules. An attendance-only member must be absent from competition discovery and blocked at checkout. Attendance groups must not generate numbered sessions or seats. Direct orchestra sales retain their existing session/quantity flow.

The attendance table records grouping and an optional planned orchestra session; it does not issue free admission, reserve orchestra capacity, mark payment or send emails. The plan may prefill paid Orchestra Assignments, while confirmation and admission handling remain separate. Existing published projections are not automatically rewritten; do not reset a live event merely to adopt this layout.
