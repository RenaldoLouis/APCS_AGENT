# Competition planning owner walkthrough

Use APCS2026 after deploying the local planning code and Firestore rules. Its prior dummy ticketing records were reset on 26 September 2026. The event is now in `draft`, with no published competition times, assignments, numbered seats or active ticket capacity. Four terminal staging bookings are retained as archived test tombstones. The local backup is at `apcs_service/.local/backups/apcs2026-ticketing-reset-2026-09-26.json.gz` and is ignored by Git.

1. In Venue Settings, confirm APCS2026's existing venue layouts, tier prices and eligibility schedule. Choose a registrant and a competition date.
2. Open **Admin Page** and select APCS2026. Confirm the board loads without redirecting to login or returning HTTP `401`. Click **Add group**, choose venue/date, leave the session unselected, drag a registrant from the pool, and save the board. Confirm the group shows “Time pending” and its name, music and video duration are visible. Open the public ticket page and confirm competition performance discovery and checkout are closed.
3. Add Group 2 and drag a different registrant into it. Move a registrant between groups, reorder within a group, search by name/music, swap, and inspect Overview. Save, reopen Admin Page, and confirm the assignments and order persist.
4. In **Performer Sessions**, create a draft slot for each group with its venue/date. Start with Group 1's time blank, then edit it to 09:00–10:00. Back on the Admin Page, link Group 1 to that matching slot and save. Edit its slot in Performer Sessions to 09:00–10:30. Reload Admin Page and confirm the same group and performers now display the new time. Link Group 2 to another nonoverlapping slot and save.
5. Try to link both groups to the same slot; confirm the UI or backend rejects the duplicate. Try to preview with an unlinked group or unused slot; confirm publication is blocked. Try to set Group 2's slot to overlap Group 1 and confirm the save is rejected without adding a public session. Keep a nonoverlapping time, reload the Admin Page, preview again, and publish.
6. Confirm both final times and ordered members remain visible on the board, now read-only. Confirm public competition sales remain closed before seats are ready. Performer Sessions must display the published event times read-only, with no direct edit or seat-generation controls.
7. On Admin Page, generate numbered seats, then select **Verify seats and mark ready**. If generation is interrupted, readiness must fail; repair inventory and retry. Once ready, confirm public and winner buyers see the published performance with its preassigned competition time and can begin checkout under the normal daily eligibility rule.
8. Confirm orchestra settings and direct public orchestra booking still use their own slots and free-seating capacity. Do not complete a payment in this walkthrough unless using an explicitly approved test contact and environment.

This walkthrough is manual because this project prohibits browser automation for UI verification. Offline tests do not prove Firestore rules deployment, transaction contention, Paper.id delivery or actual browser appearance.
